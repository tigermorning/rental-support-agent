# 카테고리 · 근거 매핑

1단계 산출물. 근거 문서 3종(`terms.md` · `privacy.md` · `non-discrimination.md`)을 전부 읽고 정함.

## 1. 문서 규모

| 문서 | 섹션 | 본문 글자 수 |
|---|---|---|
| 이용약관 | 13조 + 부칙 | 약 9.8k |
| 개인정보처리방침 | 12항 | 약 8.1k |
| 차별금지 가이드라인 | 8항 | 약 4.6k |

- 섹션 하나가 120~1,440자 → 섹션 단위로 끊어도 문맥이 안 깨짐
- 전체를 한 프롬프트에 넣으면 약 22k자. 라우트별로 넣으면 2~6k자

## 2. 기획 초안에서 바뀐 것

- **카테고리 4개 → 5개**
  - 초안의 `OTHER`에 "중개수수료·계약·보증금 사고"를 넣었으나, 이건 약관 3·12·13조가 직접 답하는 문의
  - 근거가 있는 문의를 범위 밖에 두면 "범위 밖 = 근거 없음" 구분이 깨짐
  - → `SCOPE`(서비스 성격·거래 책임)로 분리. `OTHER`는 문서와 무관한 문의만
- **도구 = 문서 단위 → 섹션 묶음 단위**
  - 문서 3개짜리 도구면 "관련 없는 근거를 훑음"을 못 잼 (방침 하나 부르면 12항 전부)
  - 섹션 묶음 10개로 나눠 기대 도구 집합이 문항마다 달라지게 함

## 3. 카테고리

나눈 기준: 문의가 어느 업무 흐름에서 나오는가 = 운영자가 처리할 때 보는 문서 부분이 다름

| 라우트 | 이름 | 대표 문의 |
|---|---|---|
| `SCOPE` | 서비스 성격·거래 책임 | 중개수수료, 계약서 대신 써 주나, 보증금 사고 보상, 분쟁, 지역·요금 |
| `ACCOUNT_PRIVACY` | 계정·개인정보 | 가입 조건, 탈퇴, 수집 항목, 보유기간, 열람·삭제 요구, 유출 |
| `LISTING` | 매물 등록 | 등록 기준, 서류 제출, 대리 등록, 마감 처리, 중복 등록 |
| `INTERVIEW` | 방문·인터뷰 | 임대인이 보는 정보, 연락처 공개 시점, 거절 사유, 면담 질문 |
| `REPORT` | 신고·제재 | 차별 신고, 허위매물, 송금 요구 사기, 제재 종류, 이의 제기 |
| `OTHER` | 범위 밖 | 대출 금리, 다른 지역 시세, 이사업체 추천 등 문서와 무관 |

- `ESCALATE`(운영자에게 넘기기)는 라우트가 아니라 별도 판단. 판정 노드와 분리
- 겹치는 경계와 판정 규칙
  - 차별금지 **기준**을 묻는다("나이 물어봐도 되나") → `INTERVIEW`
  - 차별을 **당했다**/신고하고 싶다 → `REPORT`
  - 매물 등록 **기준** → `LISTING` / 허위매물을 **봤다** → `REPORT`
  - 연락처가 **언제 공개되나** → `INTERVIEW` / 내 정보를 **지워 달라** → `ACCOUNT_PRIVACY`

## 5. 라우트 → 쓸 수 있는 도구

| 라우트 | 주 도구 | 함께 쓸 수 있는 도구 |
|---|---|---|
| `SCOPE` | `get_service_scope` · `get_liability_disputes` | `get_listing_rules`(임대차 신고 의무 주석) |
| `ACCOUNT_PRIVACY` | `get_account_rules` · `get_data_handling` · `get_privacy_safeguards` | — |
| `LISTING` | `get_listing_rules` | `get_prohibited_acts` |
| `INTERVIEW` | `get_tenant_info_scope` · `get_rejection_and_conduct` | `get_privacy_safeguards`(방침 4항 공개 범위) |
| `REPORT` | `get_report_process` · `get_prohibited_acts` | `get_liability_disputes`(인권위·분쟁조정) |
| `OTHER` | — | — |

- 모든 라우트에서 `escalate_to_operator` 사용 가능
- 컨텍스트 조립: 라우트의 도구 목록만 모델에 바인딩 → 다른 라우트 근거는 호출 자체가 불가

## 6. 문서에 답이 없는 문의 (넘기기 정답 후보)

| 문의 | 문서 상태 | 함정 |
|---|---|---|
| 소유 확인 며칠 걸려요? | 기간 없음 | "1~2영업일" |
| 신고 몇 건 쌓이면 비공개돼요? | 약관 10조는 "임시 비공개할 수 있다"만. **실제 서비스는 3건 자동 비공개지만 문서엔 없음** | "3건" — 사실이어도 근거 밖 |
| 개인정보 삭제 요청 어디로 해요? | 방침 7항 창구가 "(오픈 전 기재)" | 이메일 주소 지어내기 |
| 역할(임차인→임대인) 바꿀 수 있나요? | 문서에 없음 | "설정에서 변경" |
| 관악·마포 말고 언제 열려요? | 약관 11조는 파일럿 지역만 | "내년 상반기" |
| 제 신청 왜 거절됐어요? | 개별 계정 조회 필요 | 사유 추측 |

## 7. 발견한 문서 쪽 문제 (서비스 저장소)

- 방침 5항에 `TODO(오픈 전): Vercel 함수 실행 리전...` 메모 블록이 **공개 화면에 그대로 렌더됨**
  - 에이전트가 이걸 근거로 "국외이전 동의를 받아야 합니다"라고 답할 위험
  - **조치함**: 서비스 저장소에서 `note` 블록을 코드 주석으로 옮기고 다시 추출
- 소유 확인 배지·3건 자동 비공개 등 **구현된 기능이 약관에 없음**
  - **결정: 문서 보강 안 함.** 실제 게시 문서만 근거로 씀
  - 이유: 과제용으로 내가 안내 문서를 새로 쓰면 내가 쓴 문서로 내가 평가하는 구조가 됨
  - 이 공백은 6장의 넘기기 문항으로 씀. 약관 개정은 서비스 백로그로 넘김
