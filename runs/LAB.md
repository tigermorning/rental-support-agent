# 실험 기록

## 규칙

- eval split은 프롬프트에 넣지 않는다. 예시는 fewshot에서만
- 한 번에 하나만 바꾼다
- 바꾼 것과 숫자를 적는다. 판정을 바꾸는 실험은 2회 이상 잰다
- 근거는 정답셋이 아니라 `docs/`의 조항에서만 가져온다

### 실험 4 — 검증기 오탐: 고유어 수량

- E-018 첫 답변 "같은 집이라면 두 건을 함께 올리시면 안 됩니다"가 "2건 출처 불명"으로 걸림
  - 약관 6조 원문은 "둘 이상의 매물" — 단위가 없어 대조 실패
  - 재생성하면서 모델이 "운영자에게 전달"을 덧붙였다가 실험 2 검사에 또 걸림 → 넘김 문구로 끝남
- 수정: 원문의 고유어 수량(둘 이상, 다섯 가지)은 답변에서 단위가 달라도 허용. 아라비아 숫자("제3조")는 그대로 단위까지 일치 필요
- 확인: 저장된 모든 시도에 재생 → 바뀐 건 E-018 1건. 시험 케이스 22/22 ("둘 이상" 원문에서도 "3건"은 잡음)
- LLM 재측정은 하지 않음. 검증기는 결정적이라 재생이 곧 측정. 실험 5 측정에 함께 반영됨

### 실험 5 — 겹치는 계정 주제의 도구 설명

- 바꾼 곳: `context.py`의 `TOOL_DESCRIPTIONS` 3개
  - `get_account_rules`: "약관 5조는 로그인 링크·탈퇴 시 파기를 한 줄씩만 언급한다 — 상세는 다른 도구"
  - `get_data_handling`: 보유 기간 항목·탈퇴 후 남는 정보 나열
  - `get_privacy_safeguards`: 안전성 확보조치 세부(비밀번호 미사용·미보관 등) 나열
- 문서 구조(어느 조항이 짧게 언급하고 어느 조항이 상세한지)만 적고 평가 문항 표현은 쓰지 않음

- E-014 퇴행 원인 추정: "5조는 로그인 링크를 한 줄씩만 언급"이라는 표현이 5조를 깎아내림 → 조회하고도 그 문장을 답에서 뺌
- 판정: 2건 얻고 1건 잃음. 유지하고 실험 6에서 표현만 고침
- E-003(4회 연속 A): 답변 "계약 이행이나 보증금 반환 분쟁에 관여하지 않으며" vs must "이행·**해지** 및 분쟁" → 채점 기준 엄격 분류에 추가

### 실험 6 — 계정 도구 설명 표현

- 전: "약관 5조는 로그인 링크·탈퇴 시 파기를 한 줄씩만 언급한다 — 상세는 …"
- 후: 다루는 항목에 "이메일 로그인 링크 방식"을 명시하고, "함께 볼 곳: 탈퇴 후 남는 정보는 …, 비밀번호 저장 등 보안 조치는 …"

| 문항 | 실험 5 (2회) | 실험 6 (2회) |
|---|---|---|
| E-014 계정 도용 의심 | 2회 모두 A | 2회 모두 통과 |
| E-008 비밀번호 저장 | 2회 모두 통과 | 2회 모두 T (답변은 통과) |
| E-010 탈퇴 후 메시지 | 2회 모두 통과 | 2회 모두 통과 |

- E-008 도구 실패는 두 갈래
  - 1회차: 계정 도구 + 처리방침 도구 둘 다 호출. 답은 정확. 평가셋 작성 에이전트가 "둘 다 부르는 것도 타당"이라 올린 애매 문항
  - 2회차: 계정 도구만 호출하고 "비밀번호를 입력하거나 저장하는 절차는 없습니다"라고 답함
    - 처리방침 8항을 **읽지 않고**, 도구 설명의 "비밀번호 저장 등 보안 조치" 문구를 근거처럼 씀
    - 검증기는 조회한 조항 원문만 대조하므로 못 잡음. 채점기도 사실이 맞으니 통과
- **발견: 도구 설명 문구가 조회하지 않은 근거로 샌다.** 도구 설명에 사실 단정("비밀번호 미보관")을 쓰면 모델이 조회 없이 그 사실을 답할 수 있음
  - 실험 5의 처리방침 도구 설명에 "비밀번호 미사용·미보관"을 넣은 것부터 위험했음
  - 대응 후보: 도구 설명은 주제 이름만("비밀번호", "보안 조치")으로 쓰고 사실 단정은 빼기
- 판정: 실험 5 대비 답변 +4.8%p(두 회차 모두), 둘 다 +2.4%p, 도구 -2.3%p. 유지

### 실험 7 — 도구 설명에서 사실 단정 제거 (되돌림)

- 목적: 실험 6에서 본 누출(도구 설명 문구를 조회 없이 근거로 씀) 막기
- 바꾼 곳: 10개 설명 전부. "중개가 아님" → "중개인지 여부", "비밀번호 미사용·미보관" → "비밀번호", "거절 사유 닫힌 목록" → "거절 사유의 선택지" 등

| 문항 | 실험 6 (2회) | 실험 7 (2회) |
|---|---|---|
| E-008 비밀번호 저장 | T, T (답변 통과) | TA, TA — 계정 도구만 읽고 "약관 5조에는 비밀번호 저장 내용이 없다" |
| E-012 외국인등록번호·서버 위치 | 통과, 통과 | T, T |
| E-035 신고 몇 건이면 정지 | 통과, 통과 | T, T |
| E-015 대리 등록 | 통과, 통과 | A, A |

- 누출은 사라졌지만 E-008이 기준선 행동으로 돌아감
- 실험 6에서 모델을 처리방침 8항으로 이끈 것도, 조회 없이 답하게 만든 것도 같은 구체적 단어("비밀번호 저장")
  - 도구 선택을 돕는 구체성과 근거 누출이 한 몸이라 설명 문구만으로는 둘을 떼기 어려움
- 판정: 둘 다 통과 88.1/81.0% → 71.4/73.8%. 되돌림 (`git checkout context.py`)
- 남는 한계: 도구 설명의 사실 문구가 근거처럼 쓰일 수 있음. 막으려면 설명이 아니라 검증 쪽에서 봐야 함
  - 예: 답변 문장이 조회한 조항과 의미상 대응하는지 LLM으로 확인하는 검증 단계. 비용·지연이 늘어 이번엔 하지 않음

### A. 엉뚱한 조항 묶음

- E-008 비밀번호 저장 위치 → `get_account_rules`(약관 5조: 로그인 링크)만 읽음. 비밀번호 미보관은 처리방침 8항(`get_privacy_safeguards`)
  - 결과 답변: "약관상 비밀번호 저장 방식은 안내되어 있지 않습니다" — 문서엔 있는데 없다고 말함
- E-010 탈퇴 후 보낸 메시지 → `get_account_rules`(약관 5조: 탈퇴 시 파기)만 읽고 "안내 자료에 없음"으로 넘김. 답은 처리방침 3항(`get_data_handling`)
- 공통점: 약관 5조가 로그인·탈퇴를 짧게 언급 → 도구 설명만 보면 거기서 끝날 것 같음. 상세는 처리방침에 있음

### B. 조회 없이 넘김

- E-007 지역 확대 일정: 파일럿 지역(약관 11조)을 안 읽고 넘김 → "현재 관악·마포" 안내 누락
- E-014 계정 도용 의심: 개별 건으로 보고 바로 넘김 → 로그인 링크 방식·도용 통지 의무 안내 누락
- E-026 거절 사유 '기타'의 뜻: 일반 규칙(가이드라인 4항)으로 답할 수 있는데 개별 건으로 보고 넘김
- 프롬프트 절차 4(공백이면 조회 먼저)와 5(개별 건은 바로 넘김)가 부딪힘. 5가 이김

### C·D

- E-032 차별 구제: `get_liability_disputes`만 읽음 → 신고 방법(가이드라인 6항) 누락, 인권위 구제의 한계도 빠짐
- E-035 신고 몇 건이면 정지: 답변 끝에 "운영자에게 전달해 확인드리겠습니다"라고 쓰고 `escalate_to_operator`는 안 부름
  - 이용자에겐 넘겼다고 말했는데 실제로 안 넘어감. 검증에서 기계적으로 잡을 수 있음

### E. 목록 일부만 답함 — 채점 기준이 너무 엄격한가

| 문항 | must | 답변 |
|---|---|---|
| E-017 | 보증금 6천만원 초과 **또는 월세 30만원 초과**면 30일 이내 신고 | 보증금 1억이라고 한 문의라 "보증금 6천만원 초과 계약은 30일 이내" |
| E-027 | 국적·**출신 지역·민족**은 수집 안 함 | 베트남 국적 문의라 "국적은 수집하지 않는 정보" |
| E-015 | **본인 소유·적법 권한 주택만** 등록, 타인 매물 대신 등록 금지 | "타인 매물 대신 등록 금지" + 위임장·인감증명서 |

- E-017·E-027은 질문 맥락에 맞게 좁힌 답이라 이용자에겐 충분함
- E-015는 "적법 권한이 있으면 가능"이라는 핵심 조건이 빠져 실제로 덜 정확함
- 채점기는 규칙대로 판정했음(검증 38/38). 문제는 must가 조항 전체를 요구하는 쪽
- 평가용은 블라인드라 must를 고치지 않음
- **결정 (2026-09-17): 답변 규칙은 바꾸지 않고 실패 성격을 분리 기록**
  - E-017·E-027: 채점 기준 엄격으로 인한 실패. 이용자에게는 충분한 답
  - E-015: 진짜 실패. "적법한 권한이 있으면 가능"이라는 조건이 빠짐
  - 점수는 그대로 보고한다. 기준에 맞추려 답을 늘리면 점수는 오르지만 응대 품질이 좋아진 건 아님
