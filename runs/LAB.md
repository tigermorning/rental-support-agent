# 실험 기록

## 규칙

- eval split은 프롬프트에 넣지 않는다. 예시는 fewshot에서만
- 한 번에 하나만 바꾼다
- 바꾼 것과 숫자를 적는다. 판정을 바꾸는 실험은 2회 이상 잰다
- 근거는 정답셋이 아니라 `docs/`의 조항에서만 가져온다

## 채점기 검증 (`python evaluate.py --validate`)

| 검사 | 건수 | 기대대로 판정 |
|---|---|---|
| 모범 답안 → 통과 | 57 | 56 (98.2%) |
| must 사실 하나 뺀 답안 → 그 사실 누락 판정 | 38 | 38 (100%) |
| forbid 내용 넣은 답안 → 그 항목 위반 판정 | 57 | 57 (100%) |

- 어긋난 1건 E-023
  - must: "이름·이메일·연락처를 볼 수 없다"
  - 모범 답안: "이름이나 전화번호를 볼 수 없습니다" — 이메일 빠짐
  - 채점 규칙(목록 일부만 담으면 누락)대로 판정. 채점기가 아니라 모범 답안 쪽 누락
  - 규칙은 유지: 거절 사유 5가지처럼 목록 전체가 사실인 문항이 있음
  - 평가용은 블라인드 작성분이라 고치지 않고 기록만
- 변형 답안 만들며 생긴 일 (`scripts/make_judge_controls.py`)
  - v1: 모범 답안 전체를 다시 쓰게 함 → 생성 모델이 거짓 단정을 피함
    - 원문 그대로 돌려줌: F-012, E-013, E-021 등
    - 부정으로 바꿈: E-035 "3회 누적 시 자동 정지 여부는 확인이 필요합니다"
  - 그대로 썼으면 채점기가 맞게 "위반 아님"이라 한 것을 놓침으로 세고, 멀쩡한 채점기를 고쳤을 것
  - v2: 오답 문장 하나만 생성, 삽입은 코드가. 57건 전수 확인 후 4건 손으로 고침
    - F-010 생성 거부, E-029 단정 안 함
    - E-042 실존 강사명, E-038 실존 가능 번호 → 가상 값
